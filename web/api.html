API GUIDE FOR EVERYONE

拿到地址和 Key，
就能开始使用。

不需要懂编程。这份页面会带你把模型配置进 OpenCode、DSH、Pi、Kimi Code 或其他支持 OpenAI 兼容接口的工具。

OpenAI 兼容 · 自动同步模型能力

先准备好两样东西

Base URL（接口地址）

它告诉工具“去哪里找模型”。主入口是：

https://bakandarkfsg.com/cpa/v1

如果你拿到的是朋友通道地址，就使用朋友通道的地址，不要混用。

API Key（访问钥匙）

它告诉服务器“你是谁、可以使用哪些模型”。通常由管理员发给你。

Key 不是网页登录密码，也不要发给无关的人。

安全提示：不要把 Key 发到群聊、截图或公开代码仓库。本页面的在线查询不会保存 Key，刷新页面就会清除。

最省心的方法：自动配置

推荐先安装小配置工具。它会从服务器读取你有权使用的模型、思考强度和上下文限制，不需要手动逐项填写。

1

打开 Windows 终端。按 Win + R，输入 powershell，按回车。

2

复制下面整行到终端，按回车。它只安装配置工具，不会修改模型权限。

[Net.ServicePointManager]::SecurityProtocol = [Net.ServicePointManager]::SecurityProtocol -bor [Net.SecurityProtocolType]::Tls12; irm https://bakandarkfsg.com/cpa-sync/install.ps1 | iex

看到 cpa-sync 0.2.0 就表示安装成功。如果终端提示找不到命令，请关闭终端再打开。已经安装过旧版时，重新执行上面的安装命令即可升级。安装包支持本域名和 GitHub 两个下载源，并会自动校验 SHA-256。

3

选择你的工具，然后按对应步骤操作。

OpenCode：三条命令完成配置

把下面的地址和 你的Key 替换成你实际拿到的内容，再依次执行：

$env:CPA_BASE_URL = "https://bakandarkfsg.com/cpa/v1"
$env:CPA_API_KEY = "你的Key"
cpa-sync setup opencode --verify

看到 OpenCode configuration valid 后，重新打开 OpenCode，在模型列表中选择 cpa/... 开头的模型。

以后服务器增加或调整模型，只需运行 cpa-sync sync opencode --verify，不用重新安装。

DSH：按你使用的界面选择 profile

先执行两条环境变量命令：

$env:CPA_BASE_URL = "https://bakandarkfsg.com/cpa/v1"
$env:CPA_API_KEY = "你的Key"

再根据界面选择一条命令：

你使用的界面需要执行的命令
桌面端cpa-sync setup dsh --profile desktop --verify
终端界面（TUI）cpa-sync setup dsh --profile dsh-tui --verify
网页界面（Web）cpa-sync setup dsh --profile web --verify

配置完成后重新打开 DSH，在模型选择器中选择 CPA 提供的模型。模型修改会在下一次请求时生效。

以后同步更新时，把命令中的 setup 改成 sync，profile 保持不变。

Pi：自动同步模型和思考档位

把 你的Key 换成实际拿到的内容，依次执行：

$env:CPA_BASE_URL = "https://bakandarkfsg.com/cpa/v1"
$env:CPA_API_KEY = "你的Key"
cpa-sync setup pi --verify

看到 Pi configuration valid 后，在 Pi 中打开 /model，搜索并选择需要的模型。打开模型选择器时会重新读取配置。

Pi 的 /thinking 会只显示当前模型支持的档位。以后运行 cpa-sync sync pi --verify 即可更新。

Kimi Code：自动同步模型能力

把 你的Key 换成实际拿到的内容，依次执行：

$env:CPA_BASE_URL = "https://bakandarkfsg.com/cpa/v1"
$env:CPA_API_KEY = "你的Key"
cpa-sync setup kimi --verify

看到 Kimi Code configuration valid 后，重新打开 Kimi Code，在 /model 中选择模型。原有登录、权限和其他供应商设置不会被覆盖。

以后运行 cpa-sync sync kimi --verify 即可更新；该命令也会检查配置文件是否合法。

其他工具：不用安装同步器也能接入

在工具的“自定义供应商 / Custom Provider / OpenAI Compatible”页面填写：

设置项填写内容
Base URL / API 地址你拿到的 Base URL
API Key / 密钥你拿到的 Key
API 类型 / 协议OpenAI Chat Completions
模型 ID使用下方“查看我的模型”查询，不要自行猜测

如果工具支持自动发现模型，可以点击“获取模型”；如果它只显示模型名而没有思考强度，这是工具协议的限制，不代表模型不能思考。

查看我的 Key 能使用哪些模型

输入信息后点击查询。内容只用于当前这一次请求，不会写入浏览器存储，也不会被本页面保存。

API 参考与常见问题

工具和 API 请求使用哪些地址？
用途方法与路径
查看模型列表GET /models
查看模型完整能力GET /capabilities
发起对话POST /chat/completions
Responses 接口POST /responses

完整地址是 Base URL 加上表中的路径。所有请求都使用 Authorization: Bearer 你的Key。

为什么提示 401？

Key 缺失、复制不完整或已失效。检查是否多复制了空格，并确认 Base URL 与 Key 属于同一个入口。

为什么提示 model_not_found 或 404？

模型 ID 写错，或你的 Key 没有这个模型的权限。先用上方查询确认实际可用模型，再联系管理员调整权限。

为什么没有某个思考强度？

不同模型的档位不同。例如 Qwen4 Max 是 low / high / xhigh。以在线查询或自动同步结果为准，不要给所有模型套同一组值。

为什么提示 429？

请求过于频繁或同时运行的任务太多。稍等片刻，减少并发后再试。

如何把旧配置更新到最新模型？

OpenCode 使用 cpa-sync sync opencode --verify；DSH 使用 cpa-sync sync dsh --profile 你的profile --verify；Pi 使用 cpa-sync sync pi --verify；Kimi Code 使用 cpa-sync sync kimi --verify。

小夜 CPA 网关 · 配置遇到问题，把错误状态码和所用工具告诉店主即可，不要发送完整 Key。
